# Submission materials

Reviewable material; final acceptance requires real-provider evaluation, data-owner review, and human sign-off.

| Material | File / generated output | Status |
| --- | --- | --- |
| Ten-slide content and speaker notes | deck.json | Organized; no simulated KPIs or unmeasured savings |
| Solution PDF | output/pdf/model-risk-factory-review.pdf | Generated by scripts/build_submission.py |
| One-page architecture | output/pdf/architecture.pdf | Same builder; source follows current code |
| One-page Responsible AI | responsible-ai.md, output/pdf/responsible-ai.pdf | Technical draft; interpretation/fairness decisions need A3 |

| Submission email | submission-email.md | Draft; lead confirms final recipient/links and sends |
| Q&A | ../ss1_23_qa.md | 25 questions; owners verify and rehearse |

Generate PDFs in an isolated tool environment with reportlab:

```bash
uv run --with reportlab python scripts/build_submission.py
```

The PDFs are static review copies. The original handoff lacked the presentation-skill artifact runtime, so deck.json preserves slide content/notes/sources for editable export in a suitable environment. A later local PPTX is not automatically a finalized submission.

Check [completion status](../completion-status.md) before submission. Implementation is not deployed acceptance. The bilingual, action-by-action recording script is local-only at local/doc/demo-script.md and is not published in this repository.
